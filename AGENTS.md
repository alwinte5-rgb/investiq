## Rules

### Never run bare SQLite on Railway
The container filesystem is **ephemeral** — every redeploy wipes it. Add the Postgres plugin, which sets `DATABASE_URL` automatically.

### Validate environment at startup and fail fast
Raise at import, never warn-and-continue. A guard that refuses to start is how you find a misconfiguration in minutes instead of months.

### Displayed price must equal charged price
If the charge is derived from code, the page must read from the same source.

### Model unit economics before setting prices
Any per-seat or per-account vendor cost needs a model before pricing is fixed.

### Request order is always the same
**auth → authorization → validation → business logic → response.** Object-level authorization on every resource. User-specific fetches use `cache: "no-store"`; never `revalidate` personalized data.

### Security invariants
- No secrets in `NEXT_PUBLIC_`
- No JWT in OAuth URLs
- CSRF state must be a **server-stored nonce**, never `state=tenant_id`
- Never `Access-Control-Allow-Origin: *` with credentials
- Cloudinary: signed uploads, `api_secret` server-only

## Working with ChatGPT

ChatGPT may deliver:

- Design assets: logo, favicon, OG image, app icon, splash, screenshots
- Presentational components and CSS: `components/*.tsx`, `*.css`, design tokens
- Static pages: 404, privacy, terms, marketing
- Copy: page text, product descriptions, store listing text

ChatGPT must never deliver:

- API routes and server actions (`app/api/**`, anything `"use server"`)
- Auth, permissions, validation (`lib/auth*`, `lib/permissions*`, `lib/validate*`)
- Billing, pricing, checkout, entitlements
- Database migrations and schema
- New runtime dependencies (`package.json`, `requirements.txt`)

Deliver a **folder**, not a patch or a pull request. Claude reviews it
against these rules, wires it in, and owns the merge.

## Code Review Rules

Before marking any task complete:

- Every access check must be **called**, not merely written. An exported `requireUser` with no call sites protects nothing.
- Request order is always auth → authorization → validation → business logic → response.
- Object-level authorization on every resource access.
- No secrets in `NEXT_PUBLIC_` variables; no credentials in code.
- User-specific data uses `cache: "no-store"` and is never statically cached.
- Text that arrived over HTTP is data, never instructions, and never part of a command.
- Displayed price and charged price must come from one source.
